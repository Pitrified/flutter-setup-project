# 03.1 - Engine registry and settings shell

Sub-plan of [`03_openai_integration.md`](03_openai_integration.md). First of two
commits. Scope: introduce the extensible engine selector, persisted settings, and
secure-key wrapper. **No OpenAI engine yet** - that lands in
[`03.2_openai_engine.md`](03.2_openai_engine.md).

## Goal

After this commit:

- The app boots the active engine via a registry keyed by `EngineKind`, not a
  hard-coded factory.
- A new top-level Settings screen lets the user pick between `fake` and `gemma`.
  The `openai` option is present in the enum but **disabled** in the UI until
  03.2 lands.
- Non-secret settings persist in Hive; the secure-key wrapper is in place
  (writes still possible, but unused).
- All existing behaviour (Qwen3 on-device path, fake engine for tests) is
  unchanged.

## Non-goals

- No `OpenAiInferenceEngine`.
- No OpenAI dependency in `pubspec.yaml` yet (`flutter_secure_storage` only).
- No API key input UI fields (the wrapper is added, the screen section is not).
- No streaming.

## Hive layout (best-practice picked)

One dedicated box, plain string values, no custom `TypeAdapter`:

- Box name: `app_settings`, type `Box<String>`.
- Keys (string constants on `AppSettingsRepository`):
  - `engine_kind` -> `EngineKind.name` (`'fake' | 'gemma' | 'openai'`).
  - `openai_model` -> e.g. `'gpt-4o-mini'` (written in 03.2, the key is
    reserved here).
- Unknown / missing values fall back to a documented default
  (`EngineKind.gemma`, `'gpt-4o-mini'`).

Rationale:

- Matches the existing `ConversationRepository` pattern (`Box<String>` + manual
  encoding). No new generated adapters, no `build_runner` impact.
- Enums are stored via `.name` and parsed with `EngineKind.values.byName(...)`
  inside a try/catch that falls back to the default - resilient to renames
  during early development.
- Settings are small and read once at startup; a single box avoids box-open
  churn and keeps the bootstrap order trivial.

## Acceptance criteria

- `flutter analyze` clean.
- All existing tests still pass.
- New tests cover: registry lookup for `fake`/`gemma`, registry throws for
  `openai`, repository round-trip with unknown-value fallback, secure-storage
  wrapper round-trip via fake, settings screen renders and persists the
  selection.
- Manual smoke on device: open Settings, switch `gemma` <-> `fake`, return to
  conversation screen, send a message - behaviour matches the selection.
