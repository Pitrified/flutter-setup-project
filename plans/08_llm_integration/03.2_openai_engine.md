# 03.2 - OpenAI inference engine

Sub-plan of [`03_openai_integration.md`](03_openai_integration.md). Second of two
commits. Depends on [`03.1_registry_and_settings_shell.md`](03.1_registry_and_settings_shell.md).

## Goal

After this commit:

- `OpenAiInferenceEngine` is registered for `EngineKind.openai` and satisfies
  the existing `InferenceEngine` interface.
- The Settings screen's OpenAI section is live: API key field (obscured, save /
  clear via `ApiKeyStore`), model name field defaulting to `gpt-4o-mini`
  (persisted in Hive).
- Selecting OpenAI in the engine dropdown routes generation through the cloud
  path without any change to `StructuredInferenceEngine<T>` or downstream
  parsers.
- Internal-alpha-grade key handling only. Production-grade distribution stays
  deferred to [`04_api_key_distribution_production.md`](04_api_key_distribution_production.md).

## Non-goals

- No streaming. `InferenceEngine.generate()` stays `Future<InferenceResult>`.
- No backend proxy, Play Integrity, or key rotation.
- No pre-flight key validation - first `generate()` call surfaces failures.
- No retries beyond what `openai_dart` provides out of the box.

## Files touched

New:

- `lib/services/inference/openai_inference_engine.dart` - implements
  `InferenceEngine`. Constructor takes an `OpenAIClient` (injected for tests)
  plus the selected model name. `generate()` issues one Chat Completion with
  `ResponseFormat.jsonSchema(strict: true)`, returning `InferenceSuccess`
  with the raw JSON text on success and an `InferenceFailure` with a
  user-readable message on 401, network, or schema-rejection errors.
- `lib/services/inference/openai_client_factory.dart` - builds an
  `OpenAIClient` from the current `ApiKeyStore` value. Throws a typed
  `MissingApiKeyException` when empty so the engine can translate to a
  failure result.
- `test/services/inference/openai_inference_engine_test.dart` - uses a fake
  `OpenAIClient`. Cases: missing key, 401, network timeout, malformed JSON,
  happy path with strict schema.
- `test/screens/settings/settings_screen_openai_section_test.dart` - widget
  test for key save/clear and model field persistence.

Modified:

- `pubspec.yaml` - add `openai_dart: ^6.0.0` (approved).
- `lib/services/inference/engine_registry.dart` - replace the
  `UnimplementedError` for `EngineKind.openai` with the real factory.
- `lib/services/settings/app_settings_repository.dart` - activate the
  `openai_model` key (read/write), defaulting to `'gpt-4o-mini'`.
- `lib/screens/settings/settings_screen.dart` - replace the "coming soon"
  placeholder with the OpenAI section: obscured key field (Save / Clear),
  model name field, both visible whenever `EngineKind.openai` is selectable
  (always, per the "keep fake in the selector" decision).
- Failure UI (introduced in `06/00_error_handling.md`) - add a deep link
  back to `/settings` when the failure is a missing/invalid OpenAI key.
- Project logger call sites in the new engine - log model name, latency,
  prompt length, and token usage. **Never** log the key or the user prompt
  at info level.

## Behaviour contract

- On `EngineKind.openai` selected with no key stored: `generate()` returns
  `InferenceFailure('OpenAI key missing or rejected. Open Settings to update.')`.
- On 401 / 403 from OpenAI: same failure message, logged with the upstream
  error code (no key in logs).
- On network timeout: a distinct `InferenceFailure` with a "check connection"
  message; not retried automatically.
- On successful response: raw `message.content` (a JSON string matching
  `correctionJsonSchema`) is returned as `InferenceSuccess.rawText`.
  `StructuredOutputParser` handles the rest, unchanged.

## Acceptance criteria

- `flutter analyze` clean.
- New unit tests pass with no network calls (fake client only).
- Manual smoke on device with a real tester key:
  1. Install APK, open Settings, paste key, save.
  2. Set model to `gpt-4o-mini` (default).
  3. Select OpenAI in the engine dropdown.
  4. Send a Portuguese message on the conversation screen.
  5. Receive a structured correction parsed by the existing pipeline.
- Manual failure-path smoke: clear the key, send a message, observe the
  failure message + deep link to Settings.
